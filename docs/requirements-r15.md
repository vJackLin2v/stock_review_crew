# R15 需求定稿：LLM 输入脱敏 / 分析师节点合并 / 指数成交额回填 / 空观点修复 / 名称转回

> 2026-08-12 用户确认版。流程：multi-agent-dev 五阶段。基线：资讯屏蔽（R0 遗留，验收时一并收尾）。

## R0 遗留收尾
- 资讯屏蔽（NEWS_ENABLED 默认关）：后端已完成+测试绿；前端阶段隐藏已改未验；服务未重启、回归未跑。本次验收统一收尾。

## R1 LLM 输入脱敏（股票名称只留代码，界面照常显示）
- 口径：发给 LLM 的文本不含股票名称，只留 6 位代码；落盘报告/前端/数据层不受影响。
- 落点：① 复盘 market_data 渲染（_block_md 内字段级跳过 名称/name）；② 模拟账户 build_account_block（仅发给 LLM 的文本去掉名称，数据层保留）；③ 聊天注入上下文（stock_info/zt_pool 等）；④ 分析师工具轮返回（M4 负责）。
- 实现：新建 llm_sanitize.sanitize_for_llm(obj)（递归 dict/list，键=名称/name/股票名称 且仅股票数据容器内生效；失败返回原对象）。
- 输出铁律：prompts 增加「分析/报告只写股票代码，禁止写股票名称」（M4 落）。
- 数据字典：股票名称字段 = 涨停池 stocks[].名称、龙虎榜行、板块明细行、个股详情 name、账户持仓 positions[code].name；板块名/指数名/分析师名不脱敏。

## R2 分析师节点合并（方案 B，用户拍板）
- trend_analysts + sentiment_analysts 合并为单一「分析师复盘」节点；一次并行跑全部 5 位分析师；情绪派**不再引用趋势派结论**（去掉 trend_context 注入）。
- 进度语义保留（趋势派 n/2 → 情绪派 n/3 或统一「分析师 n/5」，前端 stage 契约同步）；job 契约（analysts_done/analysts_total=5）不变。
- 图结构：fetch → validate → news → analysts → host ⇄ debate → report。

## R3 指数成交额回填（实测定案 2026-08-12）
- 实测：腾讯日K（akshare stock_zh_index_daily_tx 同源）指数仅 6 列无成交额；东财 push2his 第 7 列=成交额（元）；通达信协议 fetch_daily(is_index=True) 含 amount（元，实测 630617145344.0）。
- 修复：_fetch_index_trend_impl 主源成功后，对 amount 缺失的指数用备用源（优先通达信协议/东财）回填当日 amount；只写 amount 字段，其他字段逐键不变（用户要求不丢数据）；回填失败静默保持 None。
- 涉及指数：上证/创业板/科创50（INDEX_CODES 三指数，深证不在列）。

## R4 空观点修复（「阿狼：本轮工具查询返回为空，无明确观点输出」）
- 根因：该句为 LLM 生成的非空 content（工具查询空 → LLM 空话），现有兜底只拦 content 为空。
- 修复：① 空观点检测（非空但无实质：过短/含「查询返回为空」「无明确观点」等模式 → 工具摘要兜底/重试/规则引擎）；② prompt 约束（工具无结果时基于已有数据输出观点，禁止空话）；③ 工具空结果显式化（「无数据（代码 X）」结构）。
- 取证：data/reviews/ 历史报告找实例，确认触发工具与上下文后最小修复。

## R5 股票代码→名称转回（方案②批量接口，用户拍板）
- 后端：POST /api/data/stock-names {"codes":[...]} → {"names":{code:name}}；无效代码忽略、失败返回 null、去重。
- 前端：聊天消息/报告渲染时 6 位代码批量查名称显示「名称(代码)」；查不到保持代码；防误伤（日期/随机数字不替换=查不到名称天然不替换）；mock 离线模式不报错。
