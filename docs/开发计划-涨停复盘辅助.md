## 二、席位获取 —— 实证结论（回答用户 D4 的分析）

**结论：席位名称可自动获取，无需人工从开盘啦抄。**
- 实测（2026-08-28 真实数据）：东财数据中心直连两个报表均正常返回，单股各 10 行（买卖前五×2 个上榜原因）：
  - 买入：RPT_BILLBOARD_DAILYDETAILSBUY，filter=(TRADE_DATE='2026-08-28')(SECURITY_CODE="000017")
  - 卖出：RPT_BILLBOARD_DAILYDETAILSSELL，同参数
  - 关键字段：OPERATEDEPT_NAME（营业部名称，如「国盛证券宁波桑田路证券营业部」「机构专用」）、BUY/SELL/NET（金额）、EXPLANATION（上榜原因）、RISE_PROBABILITY_3DAY（后3日上涨概率）、CHANGE_TYPE、OPERATEDEPT_CODE
- 注意：akshare 的 stock_lhb_stock_detail_em 封装当前版本抛 NoneType 错误（内部解析依赖页面结构），**本项目直连 datacenter 接口**，不依赖该封装。
- 对用户方案（人工标注驱动识别）的分析：**可行且采用**。
  1. 系统自动抓营业部名称 + 金额入库（数据比开盘啦更底层：买卖前五、净额、后3日概率都齐）；
  2. 内置公开游资/量化名单自动打标（C13）；
  3. **人工标注入口**：在新 Tab「龙虎榜席位」卡内点营业部名 → 标类型（游资/机构/量化/未知）+ 备注（如「XX路大佬」），写回 data/zt_tracking/seat_labels.json；
  4. 标注沉淀后，同一营业部后续自动带类型识别（即用户所说「直接获取人工标注的数据来识别」）；
  5. 开盘啦的角色：其「席位解读/涨停原因」只是另一层解读，不承担席位基础数据（我们已有）；开盘啦仅用于 D16 的题材抓包尝试。
- 边界（已获 D9 认可）：名单质量差时只做「机构 + 未知 + 人工」，但**人工标注入口保证随时可升级**。

## 三、板块生命周期跟踪（用户 D6 新增要求，已纳入）

- 板块进入关注池/轮动池的**首日起**，把池内全部涨停个股作为一个跟踪组保存；
- 此后**每个交易日收盘后**（随手动触发）更新这些个股走势：日线涨跌幅、是否再涨停/连板、是否大跌、相对板块强度、当日是否仍在上榜等；
- 板块**被踢出关注池时**：停止新增跟踪，但**已记录历史一律保留，不删除**（用户强调）；
- 踢出规则待用户确认（新分歧点 D11）。

## 四、实施步骤

### 阶段 A：数据层
1. **A1 全量涨停池** fetch_zt_full(date)：东财 stock_zt_pool_em 全量（不截断 20），字段带全（含流通/总市值、首/末封板时间、炸板次数、连板数、所属行业）；降级链：东财 → 同花顺 → Tushare 计算 → 缓存 → 缺失标注。
2. **A2 过滤**：ST/北证（复用 _filter_st_bj）+ 退市（名称含「退」+ Tushare 名单每日缓存）+ 上市未满一年（list_date <365 天；Tushare 不可用 → 标注 + 人工勾选）。
3. **A3 标签化** tag_zt_stocks：连板数、首/末封板时间、一字/T字（C15 精确优先+近似标注）、流通市值分档（C1）、与龙虎榜日级关联。
4. **A4 龙虎榜席位**：直连东财 datacenter（已实证）→ 买卖前五营业部 → 类型识别（机构专用=机构；seat_labels 命中=游资/量化；其余=未知）→ seat_labels.json 写回；并发 ≤4、单请求 ≤15s、失败退避；降级：失败 → Tushare top_inst（机构）→ 跳过并标注（绝不阻塞）。
5. **A5 题材归属**：开盘啦抓包（Playwright，需登录态实测）→ 不可用走 C16 兜底链；东财行业辅助维度。
6. **A6 板块聚类与重点关注**：按题材分组 → 板块日榜（涨停数/最高板/梯队分布/中军数/席位 flags/最早封板/代表股）；梯队完整=C3 → 重点关注；阈值可配置、人工覆盖可写回。
7. **A7 落盘**：
   - data/zt_tracking/{date}.json：每日全量快照（schema 版本化，幂等覆盖）；
   - data/zt_tracking/pools.json：板块池状态（板块、入池日、池内股票、状态 active/inactive、出池日）；
   - data/zt_tracking/follow/{board}.json：板块内跟踪个股的逐日走势记录；
   - data/zt_tracking/seat_labels.json：席位标注库；
   - data/zt_tracking/manual_tags.json：人工题材/标签覆盖；
   - data/zt_tracking/pending_manual/：待人工补充的 CSV（C18）。

### 阶段 B：分析
8. **B1 关注/轮动板块池**：窗口 5/10 交易日；C14 口径（5 天 ≥3 或 10 天 ≥5）→ 入池 + 重点关注；入池触发 D6 跟踪组。
9. **B2 板块出池判定**：按 D11 待确认规则；出池停止新增跟踪、保留历史。
10. **B3 核心股候选**（C11）：辨识度核心（语料4 四类：规则自动打标连板龙/空间龙；主营直接受益/逻辑稀缺标记「待人工确认」）+ 中军（流通市值 >100 亿 + 题材正宗 + 机游联动；趋势加分）。
11. **B4 介入方向提示（收盘版）**：情绪周期（fetch_market_sentiment）+ 板块位置规则 → 低吸/追涨/观望；LLM 无 key 时规则输出，有 key 时可加点评。

### 阶段 C：后端 + 前端新 Tab（= 设计稿 v0.2）
12. **C1 后端 API**：POST /api/data/zt-tracking/run（手动，dates 可传，job+轮询）；GET /api/data/zt-tracking?date=；GET /api/data/rotation-pool?date=&days=；POST 人工标记（题材/席位/核心股确认/标签覆盖/出池操作）。
13. **C2 前端**：新 Tab「涨停复盘」= v0.2 六张卡片（市场天气/涨停梯队/主线题材/轮动板块池/核心股池/龙虎榜席位）；席位卡内联标注；题材卡折叠交互；normalize+mock 对齐；ECharts 梯队图；红涨绿跌、降级标注、免责声明横幅。
14. **C3 手动刷新按钮** → POST run（日期可选，支持补历史）。

### 阶段 D：测试与回填

| D12 | 席位标注入口 | 同意龙虎榜席卡内联标注（含批量模式） |
| D13 | 回填与待填表 | 同意：回填最近 10 交易日；CSV 列=日期、代码、名称、题材标签、席位标注、备注 |
| D14 | 手动刷新日期粒度 | 前端仅当日按钮；**后端/数据层做好任意历史日期冗余**（run API 接受 dates 数组，数据层支持任意日期） |
