## 〇、需求理解

### 0.1 A 股超短线与游资（近几年的主流共识，方法论背景）

- **超短线**：以 T+1 为边界、持股 1~5 天的交易模式，核心是**赚钱效应与市场合力**，载体是**涨停板、连板、题材板块**；手法包括**打板（排板/回封）、低吸（分歧/深水）、半路、打首板/接力**。
- **游资**：以题材炒作+情绪周期赚取差价的活跃资金，公开踪迹是**龙虎榜营业部席位**；方法论多沉淀在淘股吧等社区（项目内 skills/yangjia/skill.json 已内置「养家心法/情绪周期」）。
- **复盘链条**（超短线通用模型，也是本需求要自动化的）：涨停/连板数据库 → 涨停原因/题材归类 → 板块梯队与主线判断 → 板块持续性/轮动跟踪 → 核心股（龙头/辨识度/中军）识别 → 结合情绪周期（冰点→启动→发酵→高潮→退潮）决定低吸/追涨时机。
- 参考来源：淘股吧复盘与方法讨论 https://www.taoguba.com.cn/Article/4587681/1 ；证券时报游资席位报道 https://stcn.com/article/detail/1420718.html ；新浪财经龙虎榜资金结构研报 https://stock.finance.sina.com.cn/stock/view/paper.php?symbol=sh000001&reportid=787150049774 ；悟道路主线热度复盘 https://wudaolu.com/t/topic/23502 ；akshare 龙虎榜席位详情接口 https://github.com/aifinlab/finclaw/blob/main/skills/akshare-lhb-detail/SKILL.md ；席位画像开源方案 https://github.com/quantskills/skill-smart-money-profiler 。

### 0.2 目标拆解（5 件事）

1. **每日数据底座**：全量涨停股 + 龙虎榜（排除 ST、退市、新股、次新股、北证）；
2. **个股标签化**：一字板 / T字板 / 几连板 / 涨停时间 / 市值分档（微盘 <20 亿、小盘 <100 亿、中军 >100 亿）；龙虎榜个股带席位（取不到则人工标记）；
3. **板块归并与分级**：涨停股按板块聚类 →「可关注板块」；梯队完整 →「重点关注」；
4. **板块池与轮动**：关注板块池 + 5 天/10 天轮动池；频繁轮动 →「重点关注」；
5. **（隐含目标）核心股 + 低吸/追涨时机**：从主线板块选出核心股票，并在合适时机给出低吸/追涨提示。

### 0.3 超短语料（复盘辅助需求.md 语料 1-6）—— 必须编码进系统的规则约束

语料不是背景知识，而是**你的交易体系本身的规格说明**，直接决定各步骤的口径：

| 语料 | 提炼出的规则 | 对系统设计的约束 |
|---|---|---|
| 语料2 | 短线赚钱效应集中在**涨停梯队完整、资金抱团的主流板块**；个股独立涨停大概率一日游 | 板块聚类必须是「题材级」，不是东财行业；「梯队完整」是硬标签条件 |
| 语料2 | 龙头 = 股性优良/连板或阶段涨幅领先/逻辑最硬/涨幅领跑 四大特质，**龙头不一定是连板最高** | 核心股票不能只按连板数排序，需要多维打分 + 人工确认 |
| 语料2 | **复盘选股 → 次日盘中验证（板块联动/龙头带动性/盘口承接）→ 择机介入**，严禁隔夜无脑预判 | 系统输出建议分三段：收盘预选池（无买卖点）→ 次日盘中验证 → 介入提示；需要盘中实时数据支撑 |
| 语料3 | 题材生命力 = 多元资金参与：**游资小票造势 + 机构中军走趋势（机游联动）**；中军走强反哺短线 | 席位数据（游资/机构）不是可选项而是**机游联动判定的输入**；中军判定要看趋势（均线多头） |
| 语料3/4 | 只在**情绪分歧/冰点**介入核心辨识度，不在高潮次日做加速；情绪周期有峰谷 | 低吸/追涨时机 = 情绪周期（可用 fetch_market_sentiment）+ 板块位置双条件，不能只给静态清单 |
| 语料4 | 辨识度分类：主营直接受益（中际旭创型）/ 逻辑稀缺（英伟达型）/ 空间龙连板龙 / 大盘大跌不跌的活口 | 核心股候选要打「辨识度类型」标签，活口类需要大盘环境数据配合 |
| 语料5 | 强弱转换、竞价态度、缩量加速、放量不板离场 | 次日验证环节需要竞价数据（项目已有 auction 链）与分时数据 |
| 语料6 | 仓位管理：正常 2-3 只、2-2-2 / 111 模式、永远保留 3-4 成活钱 | 关注板块池/核心股池的输出数量应受控（建议提示榜单前 2-3 只），并附仓位建议 |
| 语料1 | 市场风格会在连板炒作 ↔ 资金抱团趋势间切换；顺势、围绕资金主流方向 | 轮动池需记录「炒作风格」维度，长期可做风格切换指标 |

### 1.2 现有数据管线与口径（必须遵循）

- 降级链：主源 → 备用源 → 本地缓存 →「数据缺失/估算」标注，绝不静默错报（docs/requirements.md §四.2）；
- 契约口径：比率一律小数、None=无数据、红涨绿跌、中文展示（§五/§六）；
- 涨停口径：主板 10%、创业板/科创板 20%、过滤 ST/北证（§六.5）；
- 东财涨停池历史保留期约 30 交易日（§四.1）——对 5/10 天窗口足够，长期需自建每日归档；
- 龙虎榜仅在 close（收盘复盘）模式取数。

### 1.3 术语解释与环境探测结论（2026-08-29）

**「历史落盘位置」是什么意思？**

步骤 4 需要「过去 5/10 天的涨停数据」算轮动。但：东财涨停池只保留约 30 个交易日；现有复盘快照 data/reviews/{date}/snapshot.json 只是前端契约快照（梯队仅首板股票、板块仅 top5/bottom5），**装不下每日全量涨停清单**。所以必须由我们自己每天把「全量涨停池 + 标签 + 板块归属 + 龙虎榜/席位」存到**我们自定义的目录**，这个目录就是「历史落盘位置」。建议：`data/zt_tracking/{日期}.json`，与 data/reviews、data/chats 平级互不干扰；5/10 天窗口从这里取历史，不依赖东财保留期。若你想放别处（data_cache/、output/）也可以。

**环境探测结论（本轮实测）**：
- KAIPANLA_COOKIE：.env 已配置，长度仅 15（偏短，**可能过期，需验证**）；
- TUSHARE_TOKEN：已配置 → 上市日期（次新过滤）、日线 open/high/low（一字/T字精确口径）、龙虎榜 top_list/top_inst 均可用；

- 开盘啦接口探测：直连 quoteboard/api/auction 返回 200 但为**页面 HTML 而非数据 JSON** → 已知端点未直接返回数据，**判定需抓包确认真实接口**（可复用项目已装的 Playwright / browser_crawler.py 打开复盘页监听网络）；确认前题材/涨停原因一律走「同花顺概念 → LLM 归纳 → 人工标注」兜底；

## 二、需求步骤逐条分析（可行性 + 差距 + 执行方法）

### 步骤 1：获取每天所有涨停股票、龙虎榜（排除 ST、退市、新股、次新股、北证）

**可行性：基本可行 ✅（涨停池 ✅、龙虎榜 ✅、排除规则 70% 已有，需补 2~3 个过滤）**

- 已具备：
  - 涨停池 fetch_zt_pool(date)：东财主源含 代码/名称/涨跌幅/最新价/涨停价/换手率/连板数/所属行业/成交额/封板资金/首次封板时间/最后封板时间；备用同花顺、Tushare 自算。
  - 龙虎榜 fetch_lhb(date)：东财 → Tushare，个股级买卖额与上榜原因。
  - 过滤 _filter_st_bj：已排除 ST/北证（8/4/92 前缀）。
- 差距与执行方法：
  1. **全量**：limit_up.stocks 当前只取前 20 条（zt_rows[:20]）——新增全量模式或放开截断（一次请求可拿当日全部，通常几十~一百多只）；
  2. **退市过滤（方案已定）**：①名称含「退」+ ②Tushare stock_basic 退市名单（list_status != L 或 delist_date 已至，每日缓存）双保险。依据：2020 退市新规后，沪深主板退市整理期（15 个交易日）内证券简称**必带「退」字**，2024「国九条」后退市提速，靠名称规则基本覆盖，名单兜底防遗漏；
  3. **新股/次新过滤（口径已确认）**：**上市未满一年统一过滤**——Tushare stock_basic.list_date 距今 <365 天即剔除（自然覆盖 N/C 前缀新股）；Tushare 不可用时降级标注 + 前端人工勾选；
  4. **落盘**：每日全量写 data/zt_tracking/{date}.json，不依赖东财 30 日保留期。

### 步骤 2：打标签——一字板/T字板/几连板/涨停时间/市值分档 + 龙虎榜席位（不可得则人工标记）

**可行性：连板/涨停时间/市值 ✅（东财池自带）；一字板/T字板 ⚠️ 需派生；席位 ❌ 需新数据源或人工兜底**

- 几连板：东财池「连板数」字段已有（tier 已按此聚合）；
- 涨停时间：「首次封板时间」「最后封板时间」已有——建议以首次封板时间为排序主键，保留最后封板时间用于识别尾盘回封；
- 市值分档：把「总市值」「流通市值」列加进行输出，**按「流通市值」分档（已确认）**：微盘 <20 亿、小盘 <100 亿、中军 >100 亿；总市值仅辅助显示；
- 一字板 / T字板（需派生，口径建议）：
  - **一字板** = 开盘价即涨停价且全天未开板（炸板次数=0，open ≥ 涨停价 且 high/low ≥ 涨停价）；
  - **T字板** = 盘中开板后回封（open ≥ 涨停价 且 炸板次数>0 或 low < 涨停价，收盘仍涨停）；
  - 近似口径可用东财池「炸板次数」+首封时间；精确口径用 Tushare 日线 open/high/low/close 对照 _limit_price；Tushare 不可用则降级标注；
- 龙虎榜席位：现状**无席位明细**。可行来源（按顺序）：
  1. 东财个股龙虎榜详情（akshare stock_lhb_stock_detail_em / datacenter RPT_BILLBOARD_DAILYDETAILSBUY/SELL，买卖前五营业部）——**主力方案**；
  2. Tushare top_inst（机构专用席位，免费接口的机构部分）——东财不可用时的备用；
  3. **人工标记兜底**（已确认保留）；
  - **识别目标（已确认）**：只打三类标签——**游资 / 机构 / 量化**：机构=「机构专用」席位名；游资、量化=内置名单（常用清单 + 人工维护），其余归「未知/其他」；
  - **多 N 次请求的影响（说明）**：每只上榜股多 1~2 次详情请求，单日上榜股一般 20~100 只 → 每日额外 20~200 次东财 datacenter 请求。影响三点：①耗时增加（需并发+节流，建议 ≤4 并发、单请求 ≤15s，预计批次多花几十秒）；②东财限流/临时封 IP 风险（需失败退避，并降级到 Tushare top_inst 或跳过席位、标注缺失）；③接口字段/域名可能变更（需测试注入与降级链，项目已有此模式）。**必须做成「主源失败 → 降级 → 标注」，绝不阻塞主流程**；
- 执行方法：新增纯函数 tag_zt_stocks(pool, daily_df, lhb)，输出 {code, name, board, limit_days, first_seal_time, last_seal_time, zhaban_times, cap_class, cap_total, cap_float, board_type, lhb, seats}，全部可单元测试。

### 步骤 3：按板块分类构建可关注板块；梯队完整打重点关注

**可行性：有条件可行 ✅⚠️ —— 分类轴必须是题材级（语料2/3/4 是硬约束），梯队完整度规则需定义**

- 现状：东财涨停池自带「所属行业」（东财一级行业），板块 top5 已有；fetch_sectors / fetch_sector_heat 有板块涨跌幅+领涨股。
- **关键点**：超短线的「板块」是**题材/概念**（AI算力、机器人、低空经济、存储等），东财「电子/计算机」级行业太粗，无法做语料2 的板块共振、语料3 的题材延续性判断。
- 执行方法（推荐组合）：
  - 主轴：**涨停原因/题材归属（已确认：题材）**，来源优先级：开盘啦涨停原因（已确认优先接入；项目已有 KAIPANLA_COOKIE 基建，**接口可用性需实测**）→ 同花顺概念 → LLM 归纳（复用 llm_runtime.py）→ 人工标注兜底（题材需要盘感）；
  - 辅轴：东财所属行业 + 东财概念板块成分（stock_board_concept_cons_em，对候选股反查，慢，适合离线）；
  - 板块日榜输出 {board, zt_count, max_ladder, ladder_dist, zhongjun_count, seats_flagged, seal_earliest, top_stocks}；
- **「梯队完整」定义（已确认）**：板块内涨停**覆盖首板、二板甚至更多**（梯度连续），即板数分布至少含 {首板, 2 板} 或 {首板, 2 板, 3 板+}；阈值可配置、人工可覆盖；
- **「重点关注」加分项（源自语料）**：涨停家数 ≥3、有龙虎榜承接（含机构/游资席位）、封板时间早、板块资金流入、昨日涨停今日溢价为正、**中军呈均线多头趋势（语料3 机游联动）**；
- 遗漏处理：无法归类的独立涨停（语料2 的「一日游偷袭」）在板块层直接打低权重，不做板块。

### 步骤 4：构建关注板块池 —— 5 天/10 天窗口频繁涨停进轮动池，频繁轮动打重点关注

**可行性：可行 ✅（前提：步骤 1 的数据每日落盘）**

- 前提与存储：
  - 东财 stock_zt_pool_em 约 30 交易日保留期 → 对 5/10 天窗口够用，但**必须每天抓取落盘**；
  - 现有 reviews 快照/默认 block 缓存装不下全量 → 新增 data/zt_tracking/{date}.json（全量标注涨停池+板块日榜+龙虎榜+席位）；**运行方式（已确认）= 手动触发**：提供 work/zt_tracking.py（按日期：取数→过滤→标签→板块聚类→轮动分析→落盘→输出看板 JSON），不做自动批跑；
- 判定规则（阈值可配置，先给默认值）：
  - **持续性（关注板块池）**：板块在窗口内出现涨停的天数——默认建议 10 天内 ≥2 天或连续 ≥2 天（可配置；你已确认的轮动口径见下条）；
  - **强度**：窗口涨停家数合计、最高连板高度、中军是否持续在榜；
  - **轮动频繁（已确认口径）**：**5 天内有 ≥3 天有涨停**，或 **10 天内有 ≥5 天有涨停** → 加入轮动板块池并打「重点关注」标签；
  - **风格轴（语料1）**：记录市场处于「连板炒作」还是「抱团趋势」风格，风格切换时轮动池排序变化；
  - 辅助信号：板块涨跌幅/资金流、昨日涨停今日表现（sentiment 块）、板块指数均线多头与否（fetch_sector_hist/指数日线）。

### 目标步（隐含第 5 步）：核心股票识别 + 低吸/追涨时机

**可行性：可行 ✅（规则初筛 + 现有 LLM/分析师组装）**

- **核心股 ≠ 最高连板**（语料2 硬约束）。候选打分维度：
  1. 股性（历史涨停活跃度，需历史数据）；2. 高度（连板/阶段涨幅领跑）；3. 逻辑（贴合主力题材，来自涨停原因/题材标签）；4. 涨幅领跑（阶段强度）；
  + 辨识度类型（语料4）：主营直接受益 / 逻辑稀缺 / 空间龙连板龙 / 活口（大盘大跌不跌）；
  + **核心股池结构（已确认）= 「辨识度核心」+「中军」两组**：辨识度核心=语料4 四类（主营直接受益/逻辑稀缺/空间龙连板龙/活口）；中军=流通市值 >100 亿、题材正宗、有机游联动信号（龙虎榜游资+机构席位共现，语料3）；
- **三段式落地（语料2 严禁隔夜无脑预判）——次日盘中验证环节已确认暂不做（2026-08-29）**：
  1. **收盘预选（当前首要目标）**：输出关注板块池 + 轮动池 + 核心股池（只给「观察/预选」标签，不给买卖点）；
  2. **次日盘中验证**：板块联动是否延续、龙头带动性、盘口承接（分时稳健/回踩不破关键位/主动买盘）——复用 realtime.py 与竞价链；**先记录、暂不做**；
  3. **介入提示（收盘版）**：结合情绪周期（fetch_market_sentiment，语料4/5）给出方向性提示：**分歧/冰点低吸核心辨识度**、**弱转强后追涨**、放量不板/退潮不介入；精确的盘中介入验证留待后续版本；
- 实现：规则引擎初筛（确定性、可回测）+ LLM 点评（llm_runtime.py + 5 位分析师人格，带免责声明）+ 人工确认/覆盖入口；（仓位建议语料6 已确认不输出，仅作内部参考）
