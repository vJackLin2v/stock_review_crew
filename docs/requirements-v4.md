# R8 聊天智能流程 — 需求规格（2026-08-04 用户逐条确认）

> 流程：multi-agent-dev 分层开发系统（需求确认→测试先行→四线并行→集成闸门→质量评估→验收）。
> 本文为唯一契约；与 requirements.md 冲突处以本文为准。

## 一、问题与目标
现状：聊天拿到标的就直接让分析师回答（数据不足→瞎聊/拒答）。
目标：与复盘同级的专业流水线——**问题解析 → 分析师数据需求 → 取数 → 分析师分析 → 综合总结（流式）**，过程对用户可见（仅当前步骤提示）。

## 二、流程（6 步，用户确认）
1. **问题解析**：一个 LLM 解析用户问题 → 输出结构化解析结果（标的、意图、时间范围、关注维度）；
2. **数据需求**：把解析结果交给**用户选中的分析师**，每位分析师给出「回答该问题需要的数据清单」；
3. **取数**：按清单映射到现有数据工具执行（复用降级链）；**任一关键数据取数失败 → 本轮不回答，如实告知缺失项**（用户确认 Q5）；
4. **分析**：每位分析师基于真实数据回答（提示词约束同复盘：禁止编造，缺失必须说明）；
5. **综合总结**：一个 LLM 综合各位结论输出最终总结；
6. **流式输出**：只流式输出**总结**；过程阶段以「当前步骤」提示展示（用户确认 Q3），**不展示数据需求清单**（Q7）。

## 三、确认记录（Q1-Q7）
| # | 决定 |
|---|---|
| Q1 | LLM 解析问题 → 解析结果给分析师 → 分析师出数据清单 → 再取数 |
| Q2 | 分析师由**用户选择**（保留手动多选，不自动选） |
| Q3 | 过程只显示**当前步骤**提示（类似 Codex「正在思考」），总结逐字流式 |
| Q4 | 多轮追问保留：历史消息入上下文，每轮走完整 6 步 |
| Q5 | **取数失败不回答**：如实告知缺失项并终止本轮 |
| Q6 | 免责声明必须（程序级强制，含阶段提示与总结） |
| Q7 | 数据需求清单**不展示** |
| Q8（2026-08-04 补充） | 聊天显示模式：分析阶段仅显示「分析师名正在分析…」；分析师完成后**流式展开其分析简报**，再接总结；简报 150-250 字（提示词约束） |
| Q9（2026-08-04 补充） | 在途轮次完整性：发送后切走/回历史，轮次在后台跑完整流程并落盘，回来时自动接续（轮询认领），不得丢结果 |
| Q10（2026-08-04 补充） | **多会话并发**：A 股票轮次未结束时允许发起 B 股票提问；前端在途轮次按会话分桶，互不阻塞、互不串显（B 页面不得出现 A 的流程提示） |

## 四、数据字典（新增字段）
| 字段 | 定义 | 来源 | 边界 | 单位/None |
|---|---|---|---|---|
| parse.intent | 问题意图分类（trend/sentiment/buy_point/risk/compare/other） | LLM 解析 | 未知→other | 字符串 |
| parse.target | 标的（代码或名称，归一为 6 位代码+市场） | 解析器+搜索 | 解析失败→取数前终止 | 字符串 |
| parse.time_range | 时间范围（当日/近5日/近20日/近60日） | 解析器 | 默认近5日 | 字符串 |
| need[].data_key | 分析师需求的数据项标识（映射到数据工具） | 分析师 LLM | 仅取白名单内 key | 字符串 |
| need[].reason | 该数据用途（一句话） | 分析师 | — | 字符串 |
| stage | 当前阶段（parse/need/fetch/analyze/summarize/done/error） | 引擎 | 事件字段 | 字符串 |

## 五、SSE 事件契约（新增）
```
POST /api/chat/sessions/{id}/messages/stream（复用）
事件序列：
  stage {stage:"parse", note:"正在解析问题…"}
  stage {stage:"need", note:"分析师正在确认所需数据…"}      // 不携带清单内容
  stage {stage:"fetch", note:"正在获取数据…"}               // 成功/失败仅给简短状态
  analyst_start / analyst_delta / analyst_end               // 内部执行，前端可仅显示「分析师分析中…」
  stage {stage:"summarize", note:"正在综合总结…"}
  summary_delta* → summary_end
  done {session_id, messages, disclaimer}
  error {message}                                            // 取数失败：如实告知缺失项
```

## 六、验收标准
1. 全流程：个股问题 → 6 步事件序列完整，总结流式输出、免责声明在尾；
2. **取数失败路径**：monkeypatch 取数全失败 → 回复为「数据缺失说明」，无分析、无编造；
3. 过程可见：前端按 stage 显示当前步骤提示（不显示需求清单）；
4. 多轮追问：第二轮上下文含历史消息；
5. 契约测试 + 手算用例（解析/映射/总结结构断言）+ 全量 pytest 全绿 + 真实数据冒烟。
