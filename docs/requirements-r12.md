# R12 分析师模拟账户系统 — 需求分析文档（草案，待用户逐条确认）

> 2026-08-08 提出。本文为**草案**：口径确认后才进入开发（multi-agent-dev Phase 0）。
> **硬约束：现有功能不得破坏**——全量 pytest（当前 491 passed）与一键回测（16 项）必须全绿；
> 复盘报告格式保持 R7 冻结（正文不变，账户数据作为独立结构化输出）。

## 一、需求拆解

### R12-1 账户系统
- 每位分析师（alang/爱在冰川/拔小弦/炒股养家/铁锤，**含未来新增**：按 skill id 动态开户）一个
  独立账户，初始资金 **100,000 元**；
- 账户数据落盘 `data/accounts/{skill_id}/`：`account.json`（现金/持仓/冻结）、
  `trades.json`（每笔完整交易+拒绝记录）、`snapshots.json`（每日资产快照）；
- 首次使用自动开户（未来新增分析师零改动接入）。

### R12-2 复盘内交易执行（严格 A 股规则）
- 分析师在复盘流程中调用新工具 `place_order(code, side, qty)`（方向+数量，**不指定价格**，
  价格由引擎按口径成交）→ 引擎**逐条校验**并成交/拒绝，拒绝原因中文记录；
- **规则校验清单（引擎强制，违反即拒绝+记录）**：
  1. 资金：买入金额（含费用）≤ 可用现金，超限拒绝（防「用了过多的钱」）；
  2. **T+1**：当日买入的股票当日不可卖（卖出数量 ≤ 可用持仓=总持仓-当日买入）；
  3. **涨跌停**：成交价必须落在 [跌停价, 涨停价]（主板 ±10%、创业板/科创板 ±20%，
     按前收盘价×系数四舍五入 0.01）；收盘涨停买单拒绝（封板买不进）、收盘跌停卖单拒绝；
  4. 数量：100 股整数倍；卖出 ≤ 可卖持仓（不得裸卖空）；
  5. 费用：佣金 万2.5（最低 5 元，买卖双向）、印花税 卖出 0.05%、过户费 0.001%（双向）；
  6. 规则引擎（LLM 不可用）模式下不产生新交易（账户只读快照，避免规则引擎乱下单）。
- 每笔记录：{date, code, name, side, qty, price, amount, fee, stamp_tax, transfer_fee,
  status(成交|拒绝), reject_reason, balance_after}；
- 盈亏：已实现盈亏（卖出闭环）+ 持仓市值（按最新收盘价）→ 每日资产快照
  {date, cash, position_mv, total_assets, realized_pnl}。

### R12-3 回测验证（2026-07-15 → 2026-08-07）
- 逐交易日回放 close 复盘（约 18 个交易日），分析师按账户状态做操作计划并下单；
- 输出**规则合规报告**：每分析师 违规次数（超资金/T+1/涨跌停越界/股数非整百/裸卖空）、
  成交笔数、拒绝笔数与原因分布、期末资产与收益率；
- 特别校验：是否存在「不遵守规则」「用了过多的钱」「无视涨跌停」问题——**引擎层拒绝即视为
  系统拦截成功；若发现未拦截的违规（引擎漏洞）→ 修复后重跑**。

## 四、兼容性保障（硬性要求）
1. 全量 pytest 保持 ≥491 通过；一键回测 16 项全绿；
2. 复盘报告 Markdown 格式、章节、免责声明**完全不变**（R7）；
3. 现有 API 契约不变（新增接口为增量：GET /api/accounts、GET /api/accounts/{skill_id}、

4. 无账户交易时（规则引擎/数据缺失）复盘流程与现在完全一致，账户快照仍输出（无交易）。

## 五、风险
- 分析师 LLM 工具调用可能不稳定（漏调/参数错）→ 引擎对无效调用静默忽略并记录，不阻塞复盘；
- 回测 18 天真实 LLM 成本高 → 默认规则引擎+抽样（Q6）；
- 涨跌停/费用口径与实际券商差异（已按统一口径冻结，文档标注）；
- T+1 冻结逻辑与「同日多次复盘」交互（每日一份覆盖后账户状态连续，不受复盘覆盖影响——
  账户按日期推进，不随报告覆盖回滚）。
